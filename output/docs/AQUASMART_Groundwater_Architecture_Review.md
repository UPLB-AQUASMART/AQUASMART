AQUASMART Groundwater Architecture Review

1. Executive Summary
The prototype currently combines two different data approaches. The 3D model and vertical 2D section are
conceptual visualizations generated mathematically, while the top-view map is based on actual MODFLOW 6
output from the exercise model. The browser directly loads JSON files and performs interactive discharge
changes using Gaussian approximations. FastAPI exists only as a scaffold and is not yet part of the rendering or
simulation workflow.
 Scientifically strongest component: the top-view base hydraulic heads and flow vectors, because they come
from real MODFLOW output files.
 Prototype/visual component: the 3D geometry, layer folding, terrain features, vertical section drawdown, and
slider-driven discharge changes.
 Main limitation: changing discharge, soil type, and screens does not rerun MODFLOW, so results are
scenario estimates rather than fully defensible simulations.
 Recommended direction: keep Next.js for the interface and use FastAPI + FloPy + MODFLOW 6 as a
separate scientific computation service hidden behind a same-domain API route.
Boss-ready takeaway
The system is currently a strong visualization prototype with real MODFLOW data in the top view, but it should not
yet be presented as a full live MODFLOW simulator. To make it scientifically defensible, user changes must be sent
to a backend that updates MODFLOW packages, runs mf6, reads the output, and returns refreshed JSON results.

3.1 Terrain and geometry generation
The terrain and subsurface shapes are generated using mathematical functions rather than a MODFLOW solve.
The terrain combines regional slope, sinusoidal ridges, hills, and a Gaussian river valley. Pumping depressions
and arrows are also generated through NumPy-based calculations.

 The vertical scale is intentionally exaggerated so that aquifer layers remain readable in the 3D view.
 This is useful for communication and education, but it should be labeled as conceptual visualization.

9. Proper Simulation Flow for Production
1. Next.js sends discharge, soil, enabled screens, and well configuration to the backend.
2. FastAPI validates the request using Pydantic schemas.
3. FloPy builds or modifies the required MODFLOW packages.
4. FastAPI runs the mf6 executable.
5. FloPy reads the resulting .hds and .cbc output files.
6. The exporter converts heads, flows, drawdown, wells, contours, and metadata into compact JSON.

results. This avoids request timeouts and keeps the interface responsive.

Appendix A. Suggested Supervisor Explanation
A concise way to explain the current status:
The current groundwater module is a visualization prototype that combines real
MODFLOW top-view results with conceptual 3D and section views. The interface can
already demonstrate how discharge, soil type, and well screens affect the visuals, but
those changes are currently estimated in the browser. For a scientifically defensible
version, the frontend should send the configuration to a FastAPI backend, which will
update FloPy/MODFLOW packages, run mf6, read the output files, and return new
JSON results to the Next.js interface.
